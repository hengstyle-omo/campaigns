# v44：Participants_2026 欄位重排與按欄名讀寫

更新基準：已完成 v43 的網站與 Apps Script。只需此差異包，不含素材。

## 更新順序：先部署程式，再整理欄位

**請勿在舊 v43 Apps Script 仍服務時手動搬欄。依序執行下面步驟。**

1. 從原活動 Google Sheet 開啟「擴充功能 → Apps Script」。
2. 用本包 `apps-script/DysonProgress.gs` 的完整內容取代舊程式，儲存。專案中不要同時留另一份舊版同名函式／常數；若自行新增過允許網域，請保留 `ALLOWED_ORIGINS` 的設定。
3. **先重新部署現有網頁應用程式**：「部署 → 管理部署作業 → 原部署的鉛筆 → 版本選新版本 → 部署」。執行身分與存取設定沿用，原 `/exec` 網址不變，不必修改網站 `config.js`。新版後端可先依欄名讀取原 v43 的欄位順序。
4. 回到編輯器，函式選 `setupV8`，按「執行」，需要時完成授權。這一步自動備份並整理欄位，**不用自己剪貼欄位**。
5. 等到執行記錄顯示完成，再重新整理網站，等背景同步結束。程式碼已於步驟 3 部署，單純執行設定函式後不必再部署一次。
6. 將差異包的 `2026-dyson-christmas/` 內容依原路徑合併到 GitHub 的活動資料夾，提交保存。本包只有四個檔案：Apps Script、README、VERSION、此部署說明；`.gs` 在 GitHub 作來源備份，仍須執行前述 Apps Script 更新步驟。

`setupV7()` 與 `setup()` 也會轉呼叫新版 `setupV8()`，可相容先前的函式名稱。

## 既有資料與備份

- 有參加者紀錄時，第一次執行會先複製 `Participants_2026`，命名如 `Participants_2026_backup_v44_20261024_123000` 並隱藏。只有 `Participants_2026` 為活動實際讀寫分頁；備份不參與統計或授權。
- 整理時移動的是整欄，會保留資料、格式與核取方塊，不重建參加者資料列。原領取時間、行銷意願、簽到、優惠任務、正式及模擬擺設保留。
- 既有額外備註欄保留並排在活動 47 欄之後；不會刪除。日常保存只寫活動認得的欄位，不覆蓋額外備註或公式。
- 備份名稱存於 `DYSON_V44_BACKUP` 指令碼屬性。重跑設定不覆蓋備份，也不清空活動紀錄；重跑會再次套用本文件的建議欄位順序。
- 若舊 Preview／Bonus 已完成 v43 遷移或已刪除，本版不需要它們。若為尚未遷移的舊版，程式仍保留一次性舊資料匯入功能。
- 若執行中途失敗，請保留備份與目前分頁，修正執行記錄中的問題後重跑 `setupV8()`。調整過程會暫停進度服務寫入，成功後才恢復，避免使用未完成的欄位配置。

## 之後如何自行調整

1. 請選整個欄位，使用 Google Sheet 的移動欄方式，連同標題與資料一起移動。
2. 47 個必要欄名請維持原名且各出現一次；不要只搬第一列標題，不要另建第二個同名欄。
3. 可以隱藏／展開欄位，或增加自己的備註、標記與公式欄。
4. 日常移動整欄後不用執行 `setupV8()`，否則會重新排回本文件的預設順序。為避免移動當下與使用者保存交錯，請在活動使用量較少時一次完成欄位調整。
5. 管理資格由「是否管理者」的欄名定位；無論放到哪一欄，仍由這個核取方塊控制。

程式遇到缺少／改名／重複的必要欄位會回報錯誤並停止寫入。請還原欄名後再重試，不要透過刪除資料來排除錯誤。

## 驗收

- 確認 A 是 Email、B 是是否管理者，原管理帳號勾選仍在。
- 相同 Email 重新整理，收藏、簽到、位置與卡片任務維持；行銷勾選及取消可保存。
- 管理者模擬日期、放入物件後重新整理可接續；退出模擬不增加正式紀錄。
- 可用測試帳號確認，移動整欄後仍能正確保存；自訂備註／公式欄未被覆寫。

本次完成本地遷移與欄位重排測試，以及 v43 網頁連接新版後端的 Chromium 整合測試；尚未直接修改你的正式 Google Sheet。
