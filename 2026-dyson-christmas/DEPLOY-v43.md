# v43 差異更新與 Apps Script v7 部署

更新基準：已上傳的 v42。此包只含變更檔，不必重新上傳圖片、音樂或字型。

## 1. 備份既有 Sheet

在 Google Sheet 建立副本，保留正式參加者、Preview 與 Bonus 分頁。既有資料欄請勿刪除或重新排列。

## 2. 更新既有 Apps Script

1. 從目前活動使用的 Google Sheet，點「擴充功能 → Apps Script」。
2. 將包內 `apps-script/DysonProgress.gs` 的完整內容複製到原本的程式檔，取代舊 v6 程式。專案內不要同時保留另一份同名函式／常數的舊程式。
3. 儲存，於上方函式選單選 `setupV7`，按「執行」。第一次需要時完成授權。
4. 確認執行成功，並在 `Participants_2026` 看見以下新增欄位。原有前 40 欄保留。

| 欄 | 欄名 | 用途 |
| --- | --- | --- |
| AO | 是否管理者 | 勾選後顯示模擬、管理畫面及全部十款限定動物 |
| AP | 卡片任務完成 | 正式帳號是否下載／成功分享過一次卡片 |
| AQ | 卡片任務時間_台灣時間 | 首次任務保存時間 |
| AR | 卡片任務格式 | png／gif／mp4 |
| AS | 卡片任務方式 | download／share |
| AT | 模擬日期 | 管理者上次選擇的模擬日期 |
| AU | 模擬進度_JSON | 模擬收藏、擺設、簽到及獨立卡片任務 |

`setupV7()` 保留原領取紀錄、位置、行銷意願及參與日期。正常重跑不重做一次性遷移，也不重設管理者勾選。

## 3. 遷移與管理者設定

- 第一次執行會將舊 `Preview_2026` 內有效 Email 對應到同一個 `Participants_2026` 資料列，自動勾選為管理者，並將舊模擬內容轉存 AT／AU；不混入正式收藏及簽到。原本沒有正式資料列者會建立一列。
- 舊 `Preview_2026` 與 `Bonus_Access_2026` 保留備份，不再作為日常權限來源。Bonus 舊欄名「橘貓」改「貓」、「海豹」改「小海獅」，不改資料值與動物 ID。
- 本版以「是否管理者」作為限定動物及管理介面的共同開關；舊 Bonus 個別動物勾選不再控制權限。管理者看全部十款，其他 Email 不顯示限定區。
- 若沒有舊 Preview 紀錄，先從新版網站以要使用的 Email 保存一次，再到該列 AO「是否管理者」勾選。重新整理網站並等背景同步完成即可。
- 取消管理資格後，下一次伺服器同步會隱藏管理功能；後端也拒絕該 Email 的模擬寫入。前端送出的管理者布林值無法自行授權。
- 這是先前確認的免驗證 Email 方案，並未加入密碼、驗證碼或 Google 登入。

## 4. 重新部署同一個網址

1. Apps Script 右上「部署 → 管理部署作業」。
2. 選目前網站使用的網頁應用程式部署，按編輯（鉛筆）。
3. 版本選「新版本」，描述可填 `v43 / service v7`。
4. 保留既有設定：執行身分為擁有者，可存取的使用者為「所有人」，按「部署」。

**編輯現有部署可沿用相同 `/exec` 網址。** 不必另外按「新增部署」。本包 `config.js` 已沿用既有網址；若另建部署產生新網址，才需同步修改 `window.DYSON_CLOUD_CONFIG.endpoint`。

後端 `ALLOWED_ORIGINS` 預設允許既有 GitHub Pages 網域。如果未來直接以其他網域載入活動，須加入該頁面的 HTTPS origin 並重新部署；僅作短網址轉址不需加入轉址來源。

## 5. 覆蓋 GitHub v42 檔案

將本包 `2026-dyson-christmas/` 內檔案按原路徑合併至 `campaigns/2026-dyson-christmas/`，提交並推送。不要刪除未包含在差異包內的檔案。

本次共八個檔案：`index.html`、`README.md`、`VERSION.txt`、`DEPLOY-v43.md`、`assets/css/style.css`、`assets/js/app.js`、`assets/js/config.js`、`apps-script/DysonProgress.gs`。其中 `.gs` 放 GitHub 是方便保存程式來源，仍需依步驟 2 複製到 Apps Script。

確認 GitHub Pages 已完成部署，再重新整理。頁面資源版本標記為 `20261024-progress-v43`。新版前端要求後端 `serviceVersion: 7`、`rulesVersion: 3`，只更新前端或只儲存 `.gs` 而未重新部署都不會完成本次更新。

新檔不包含硬編碼的私人管理 Email；既有 Git 歷史不因覆蓋檔案而消失。

## 6. 部署後驗收

- 全新瀏覽器只出現同一個介紹／Email 視窗，行銷預設不勾；留白可開始體驗，不呼叫 Sheet。
- 填 Email 按「開始收藏」建立一列，介紹收起後背景同步；回訪相同 Email 接續紀錄。
- 勾選行銷後保存、重新整理仍勾選；取消後重新整理仍不勾選。
- 管理者勾選生效後顯示日期模擬與十款動物；模擬不改正式領取數、簽到或卡片任務。
- 正式活動期間領取產品只保留對應優惠。製作卡片但不下載／分享不解鎖；取消分享不解鎖；下載或成功分享一次並完成 Email 同步後解鎖。之後新收藏產品不需再做卡片。
- 未填 Email 時下載卡片，再填 Email，任務與合法日期的本機進度一併保存。同一瀏覽器清除網站資料前尚未雲端同步的紀錄可能遺失。
- 實際十個不同活動日期的參與，才能解鎖第五張全品項優惠；同日補領不會累加十天。非活動期間的正式帳號不能領取新禮物，可用管理者模擬檢查畫面。

本版已做本地 Sheet 模擬、快取／權限與介面整合測試；未對正式 Sheet 寫入測試，也未執行真實 Google 一萬人壓力測試。MP4 錄音與行動裝置分享仍需在實際裝置驗收。
