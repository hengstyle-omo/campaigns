此版本讓一般使用者只填 Email，按台灣時間每天體驗 12 月的禮物開放流程。已完成程式與隔離測試，尚未更新你的正式 Apps Script、Google Sheet 或 GitHub Pages，也沒有清除任何線上資料。

最新預設為左樹、中屋、右雪橇，三件均比初版放大 20%；若已安裝起始雪境，單純這次位置大小更新只需更新前端，不用重部署 GS。詳見 STARTER-LAYOUT.md。

此版已加入預設暖窗小屋、雪地小樹與兒童木雪橇；可移除、調整並以 Email 保存，不計入每日收藏或參與天數。Day1 仍是第一場雪。正式網站尚未套用此改動。

若上一版 11 月測試已可運作：覆蓋測試網站資料夾，更新 GS 並將原部署切換新版本即可。已有 `Participants_Test_2026` 且正常者，不必重跑設定，也不用清空資料或新增欄位。細節見 STARTER-SCENE.md。

   - 函式選單選 `setupNovemberTest`，執行一次。它會在原本同一份試算表建立 `Participants_Test_2026`，不會複製正式參加者，也不會清空正式或已有的測試資料。
   - 若原活動尚未完成初次設定、缺少 `DYSON_SPREADSHEET_ID`，才先從原試算表執行 `setupV10`；已正常使用的活動不必重跑。

   - 「部署 → 管理部署作業 → 編輯原有效部署 → 版本選『新版本』→ 部署」。沿用原 `/exec` 網址，包內已保留現有網址，不用再建立另一個部署。
   - 單純儲存 GS 不會更新公開部署。請勿用 `/dev` 測試部署網址給一般人使用。
3. **上傳獨立測試網站**
   - 將本包的整個 `2026-dyson-christmas-test/` 資料夾放到 GitHub `campaigns` 儲存庫根目錄，與原本 `2026-dyson-christmas/` 並列，提交後等待 Pages 部署完成。
   - 只有 `2026-dyson-christmas-test/` 要上傳網站；`GS/`、根目錄 SETUP.md 與測試結果不必上傳。
   - 上傳後預期路徑是 `https://hengstyle-omo.github.io/campaigns/2026-dyson-christmas-test/`。此網址尚未由這次工作部署，完成上傳前不保證可開啟。

每天台灣時間 00:00 換日，不用手動修改設定。11 月開始前或 11 月結束後，這個測試入口不會開啟新領取。12 月正式活動仍使用原正式網站與真實日期。

一般人不能自由選日期。新加入者預設沒有管理權限；正式表中已是管理員的 Email，在測試分頁也不會自動取得管理權。只有你另外在測試分頁勾「是否管理者」的人，才會要求原管理碼並開啟進階模擬。

## 可以確認的流程

- 當日及以前禮物可領取，未來禮物鎖定。
- 領取、放入、移除、位置調整與再次讀取。
- 同一 Email 在其他裝置重新載入測試進度；正式與測試各自獨立。
- 每個不同日期只計參與一天；同一天補領多份不會多算。
- 累積 10 個測試日期可測護照資格；商品券仍需完成一次卡片下載／分享任務。
- 製作卡片、音訊與商品介紹沿用已確認的 A 圖版本。

## 資料與正式活動的關係

- 正式網站仍讀寫 `Participants_2026`；測試網站只讀寫 `Participants_Test_2026`。兩者沿用同一個 GS 部署網址，依明確的測試環境與專用操作分流。
- 測試使用獨立的瀏覽器快取與圖片資料庫，不會載入正式版的收藏、Email 或素材覆蓋。
- 測試頁停用 GA，避免測試流量進入正式活動數據。
- 測試頁的三個已提供商品序號加上 `TEST-`，BP10 未提供的序號仍留白；測試優惠與護照資格不得兌換。頁首、開場與分享文字有測試版標示。
- 領取與參與日期依後端台灣時間判斷。前端改電腦日期不會讓 GS 提前開放未來的禮物。
- GS 尚未更新時，測試頁會停止同步。每個測試寫入使用舊 GS 不支援的專用操作，避免舊服務把測試資料當成正式資料。
- 一般 Email 仍是活動識別，沒有驗證信箱持有人；請使用各自的 Email 測試，不需提供個人密碼。

你提到會在正式上線前清空資料；這次沒有加入自動清空功能。測試進度本來就不會帶入正式活動，清理前仍建議保留備份，並保留欄位名稱與需要的管理員權限設定。
